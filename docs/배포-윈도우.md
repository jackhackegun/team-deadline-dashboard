# 윈도우 데스크탑에서 배포하기

맥에서 개발한 것을 윈도우 PC로 옮겨 Docker로 띄우는 절차.

---

## 0. 윈도우에 미리 설치할 것

| 프로그램 | 확인 방법 |
|---|---|
| **Docker Desktop for Windows** | 설치 후 실행해두면 트레이에 고래 아이콘. `docker --version` |
| **Git for Windows** | `git --version` |

Docker Desktop은 설치 중 **WSL 2** 사용에 동의해야 한다. 이미 켜져 있지 않으면 설치 프로그램이 안내한다.
설치 후 **Docker Desktop을 실행한 상태**여야 `docker` 명령이 동작한다.

> 폴더 경로에 한글이나 띄어쓰기가 없는 편이 편하다. 예: `C:\projects\team-dashboard`

---

## 1. 코드 가져오기

PowerShell을 열고:

```powershell

cd team-dashboard
```

이미 클론해둔 게 있으면 최신으로만 맞춘다.

```powershell

```

## 2. `.env` 만들기 — 가장 중요한 단계

`.env`는 **저장소에 올라가지 않는다**(시크릿이라 일부러 제외했다). 윈도우에서 새로 만들어야 한다.

```powershell
Copy-Item .env.example .env
notepad .env
```

`JWT_SECRET`과 `POSTGRES_PASSWORD` 두 줄을 채운다. 값은 아래 명령으로 만든다.

```powershell
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$bytes = New-Object byte[] 32
$rng.GetBytes($bytes)
($bytes | ForEach-Object { $_.ToString('x2') }) -join ''
```

한 번 실행할 때마다 랜덤 값이 하나 나온다. **두 번 실행해서 서로 다른 값을** 각각 붙여넣는다.

> Git Bash를 쓴다면 `openssl rand -hex 32` 한 줄이면 된다.

채운 모습:

```
JWT_SECRET=3f9a...(64자)
POSTGRES_PASSWORD=8c21...(64자)
ALLOWED_ORIGINS=http://localhost:8080
WEB_PORT=8080
```

**두 값이 비어 있으면 컨테이너가 아예 뜨지 않는다.** 개발용 기본값이 운영에 올라가는 사고를 막으려고 일부러 그렇게 만들었다.

## 3. 띄우기

```powershell
docker compose up -d --build
```

처음에는 이미지를 받고 빌드하느라 몇 분 걸린다. 끝나면 확인한다.

```powershell
docker compose ps
```

`api`와 `db`가 `healthy`, `web`이 `Up`이면 된다.

브라우저에서 연다.

```
http://localhost:8080
```

---

## 4. 맥에서 쓰던 데이터 옮기기 (선택)

새로 시작할 거면 이 단계는 건너뛴다. 계정·팀·할 일을 그대로 가져오려면:

**맥에서** 백업 파일을 만든다. (이미 `backup-YYYYMMDD.sql`로 만들어 두었다)

```bash
docker compose exec -T db pg_dump -U dashboard --clean --if-exists dashboard > backup.sql
```

이 파일을 USB나 메신저로 윈도우 PC의 프로젝트 폴더에 옮긴 뒤, **윈도우에서**:

```powershell
Get-Content backup.sql | docker compose exec -T db psql -U dashboard -d dashboard
```

복원 후 기존 계정과 비밀번호가 그대로 동작한다.

> `backup.sql`에는 비밀번호 해시가 들어 있다. **깃허브에 올리지 말 것.**
> (`.gitignore`에 `*.sql`을 넣어 두어 실수로 커밋되지 않는다.)

## 5. 평소 쓰는 명령어

```powershell
docker compose ps              # 상태 확인
docker compose logs -f api     # 로그 보기 (Ctrl+C로 빠져나옴, 서버는 계속 돎)
docker compose down            # 서버 끄기 (데이터는 남음)
docker compose up -d           # 다시 켜기
docker compose down -v         # 데이터까지 완전 삭제 — 되돌릴 수 없음
```

명령어는 반드시 `docker-compose.yml`이 있는 폴더에서 실행한다.

Docker Desktop이 켜져 있으면 PC를 껐다 켜도 컨테이너가 **자동으로 다시 올라온다**(`restart: unless-stopped`).

## 6. 다른 사람도 쓰게 하기

### 6-1. 같은 와이파이 (팀원이 같은 공간에 있을 때)

윈도우 PC의 내부 IP를 확인한다.

```powershell
ipconfig | Select-String "IPv4"
```

`192.168.0.15` 같은 값이 나오면, 팀원은 브라우저에 그대로 친다.

```
http://192.168.0.15:8080
```

**`.env`는 고치지 않아도 된다.** nginx가 화면과 API를 같은 주소로 내려주기 때문에
브라우저 입장에서는 CORS가 발생하지 않는다. (`ALLOWED_ORIGINS`는 화면과 API를
서로 다른 주소에 올릴 때만 필요하다.)

처음 접속할 때 **윈도우 방화벽이 물어보면 '허용'** 을 눌러야 한다.
물어보지 않았는데 팀원이 접속을 못 하면 방화벽에서 8080 포트를 직접 열어준다.

```powershell
New-NetFirewallRule -DisplayName "Team Dashboard 8080" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow
```

> 이 명령은 관리자 권한 PowerShell에서 실행한다.

### 6-2. 인터넷 어디서나 (팀원이 집에서 쓸 때)

같은 와이파이가 아니면 위 주소로는 접속되지 않는다. 터널을 열어 공개 주소를 만든다.
**Cloudflare Tunnel**이 계정도 결제수단도 없이 바로 쓸 수 있다.

```powershell
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:8080
```

실행하면 `https://<랜덤이름>.trycloudflare.com` 주소가 화면에 찍힌다.
이 주소를 팀원에게 주면 어디서든 접속된다. HTTPS도 자동으로 붙는다.

알아둘 것:

- **창을 닫으면 끊긴다.** 쓰는 동안 그 PowerShell 창을 켜 둬야 한다
- **주소가 매번 바뀐다.** 고정 주소가 필요하면 Cloudflare 무료 계정 + 도메인이 필요하다
- **인터넷에 공개된다.** 주소를 아는 사람은 누구나 회원가입할 수 있으니 아무 데나 뿌리지 말 것
- 여기서도 `.env`는 고칠 필요가 없다

### 6-3. PC를 안 켜도 되게 하려면

위 두 방법 모두 **윈도우 PC가 켜져 있어야** 한다. 24시간 돌리려면 클라우드 서버가 필요하고,
대부분 결제수단 등록을 요구한다. 학기 중 팀플 용도라면 6-1이나 6-2로 충분하다.

## 막힐 때

| 증상 | 원인과 해결 |
|---|---|
| `docker : 명령을 찾을 수 없습니다` | Docker Desktop 미설치 또는 미실행. 실행 후 트레이 아이콘 확인 |
| `no such service: api` | `docker-compose.yml`이 없는 폴더에서 실행했다. `cd`로 프로젝트 폴더로 이동 |
| `JWT_SECRET을 .env에 설정하세요` | 2단계를 건너뛰었다. `.env`의 두 값을 채울 것 |
| `port is already allocated` | 8080을 다른 프로그램이 쓰고 있다. `.env`의 `WEB_PORT`를 8081 등으로 변경 |
| 화면은 뜨는데 로그인이 안 됨 | 새 DB라 계정이 없다. 회원가입하거나 4단계로 데이터 복원 |
| 컨테이너가 계속 재시작 | `docker compose logs api`로 원인 확인 |
